# جرد الواجهة الأمامية والمسارات

> **النسخة اللي اتراجعت:** source snapshot `eab70cc`، مقارنةً بـ `main` عند `5b45806`. HEAD الحالي `af5cdf9` خاص بتغييرات توثيقية؛ ما اتعدّلتش ملفات التطبيق.

## حدود المراجعة وحالة اللقطات

- ده inventory للكود مع browser captures التقطها الـ parent على التطبيق المحلي، بحساب Admin حقيقي وقاعدة بيانات disposable فاضية. مسارات Public/Auth اتصورت وإحنا signed out؛ مسارات Workspace/Admin بجلسة Admin. مافيش بيانات fake اتضافت.
- الـ manifest فيه **68 concrete route** وكل واحدة متصورة EN وAR، يعني **136 route/locale screenshot موجودة**. إجمالي السجل **356 capture records** (204 route records فيها تكرارات، و152 سجل تفاعل). كل العمليات متعلمة `ok: true`، وده معناه إن capture نجح بس؛ مش ضمان لنجاح API أو hydration أو provider.
- فيه **8 سجلات تفاعل لـ Create مافيهاش PNG**: Graphic Layout، Ad Concept Short، Explainer، وUGC Clip باللغتين. ما ربطتش لها صورة غير موجودة؛ موجودة كـ manifest-only في JSON.
- بيانات التقاط المتصفح في [`evidence/browser-captures.jsonl`](evidence/browser-captures.jsonl)، والـ route schema الكامل في [`evidence/frontend-routes.json`](evidence/frontend-routes.json). روابط الصور تحت `screens/` متطابقة مع أسماء الملفات في الـ manifest.

## Tabs والـ controls اللي تتجرّب

- `/scout/social` و`/scout/maps` (في واجهة Admin): Active Workspace، Org Social Jobs، Org Maps Jobs. الأعداد ممكن تتغير، والـ selectors بتتعامل مع الاسم كبادئة.
- `/guide` و`/admin/guide`: Overview، Discover، Intelligence، Create، Performance، Admin. الـ screenshots تظهر المحتوى الفعلي لكل حالة ومربوطة في جدول المسارات.
- `/admin/updates`: Editor وPreview. `/admin/support`: filters للـ Status (All Statuses/Open/In Progress/Resolved) والـ Type (All Types/Bug Reports/Feedback Ideas/Support).

- Tabs الظاهرة في المصدر عبارة عن buttons/local state؛ ما اتلاقاش `role="tab"` أو `tablist` للصفحات دي. `aria-selected` في Discover results row والـ docs search option مش معناه إن دي tabs.

## ملاحظات browser مهمّة

- `/api-keys` كرابط مباشر رجّع backend `{"detail":"Not Found"}` في EN وAR (اللقطات `api-keys-en.png` و`api-keys-ar.png`). في إعداد Vite المحلي، proxy البادئة `/api` بتلتقط المسار ده. فيه capture منفصل لـ SPA navigation جوه React في JSON؛ افحص direct URL والتنقل الداخلي كمسارين منفصلين، وما تعتبرش الـ 404 دليل إن component نفسه بيرندر كده.
- حسب ملاحظة الـ parent، `/admin` و`/dashboard` ظهروا لسه loading بعد حوالي ثانية. الـ manifest فيه captures منفصلة باسم `tab-settled` للغتين، لكن مافيش دليل sustained كفاية على صحة الخدمة؛ ما نوصفش المسارين `broken` من الملاحظة دي لوحدها.
- الـ DB فاضية وdisposable؛ لذلك empty lists أو بيانات غير ظاهرة مش دليل إن endpoint فاشل. كل اللقطات تثبت شكل الحالة اللي اتصورت فقط، مش نجاح provider أو استمرارية البيانات.

## API wiring، billing، والإفصاحات

- حدود الخدمات في `src/services/index.js`، تطبيقات API في `src/services/api/`، mocks في `src/services/mock/`، والنقل المشترك في `src/services/http.js`. `VITE_DATA_SOURCE` افتراضه API وproduction build بيرفض mock، لكن الكود مش إثبات إن أي request حقيقي نجح.
- API families في JSON تشمل `/auth/*`, `/account/*`, `/admin/*`, `/discovery/jobs*`, `/creatives*`, `/patterns*`, `/insights*`, `/media/jobs*`, `/scout/*`, `/monitors*`, `/notifications*`, `/dashboard/metrics`, `/playbooks*`, `/support/tickets*`, و`/updates*`؛ كل route مرتبط بخدماته في JSON.
- `/billing` يعرض usage/access وطلبات وصول يراجعها Admin؛ ما لقيناش checkout/payment provider. `/admin/subscriptions` لإدارة خطط واستحقاقات داخلية، مش دليل على دفع. خفّوا trial countdown أو أي إيحاء شراء لحد ما يبقى فيه flow/backend/payment فعلي ومتطابق.
- `DataSourcesPage` ممكن يعرض “Operational & Available in failover stack” لمصدر مش متطابق مع provider response؛ ده يوحي بصحة من غير دليل. اعرضوا status unavailable لو مفيش health result محدد. كمان وضّحوا إن AI/inferred signals ممكن تكون تقديرية، وخلي الوثائق القانونية تراجع وتتوافق عليها جهة بشرية.
